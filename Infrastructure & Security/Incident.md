# Phase 3.1: Security Incident

A secondary reason I wanted to host the Chamilo web application online was to demonstrate it during my capstone meeting. I assumed that having it publicly accessible for a few days would be relatively safe, but I may have been wrong about that assumption.

There are several reasons for this concern. First, I performed next to no security hardening on the host machine. I did not containerize the application using Docker, segment the server using a VLAN + firewall, or implement any significant OS or application-level security controls. Realistically, I should have also configured Cloudflare Access authentication for Chamilo, which would have prevented unauthenticated requests from reaching the application through the tunnel. Although Chamilo has its own authentication mechanism, I was not entirely confident in relying on it alone. During the quick installation process, I also failed to realize that Chamilo 3.0.x was available, with security improvements over earlier versions. Additionally, I had not reviewed or hardened the default configurations of Apache and MariaDB.

These concerns did not arise out of nowhere. Out of curiosity, I was exploring the Cloudflare dashboard for my domain when I came across the analytics section. To my surprise, I was far from the only person accessing my site. Cloudflare had recorded **over 1,500 requests**, a large portion of which resulted in HTTP 4xx (825 requests) or 5xx (87 requests) responses. Upon examining the requested paths, I noticed patterns consistent with automated vulnerability scanning. Several requests attempted to access `.env` files, configuration files, and `.json` files containing variations of credential-related names. This suggests that automated scanners were probing my application for potentially exposed sensitive information. While these requests do not necessarily indicate a successful compromise, they certainly warrant further investigation.

**This is FASCINATING!** I finally have an opportunity to apply some of the knowledge I've gained while studying for CompTIA Security+, and potentially walk through an entire incident response cycle. How cool is that?!

At the moment, I am working through **detection and analysis**. I have identified potentially suspicious traffic targeting an inadequately hardened web server, and my next step is determining whether any of these requests resulted in unauthorized access. To investigate, I plan to examine the server's SSH authentication logs, Apache access and error logs, MariaDB logs, and relevant system logs. Before making significant changes, I will preserve copies of the available evidence and generate SHA-256 hashes to help verify their integrity. If I discover evidence of a compromise, I will proceed with containment and eradication. 

I'll be sure to document my findings and write a lessons-learned report after this whole fiasco...
